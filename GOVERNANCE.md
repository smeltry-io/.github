# Governance

## Current Status

Smeltry is an early-stage project under **BDFL (Benevolent Dictator For Life)** governance.
This is a deliberate starting point: one maintainer, clear decision-making, fast iteration.

As the project gains contributors and adopters, governance will evolve toward a
multi-maintainer model (see [Becoming a Maintainer](#becoming-a-maintainer)).

## Decision Making

All technical and project decisions are made by the current maintainer(s).

For non-trivial changes, the preferred process is:
1. Open a GitHub Issue to describe the problem or proposal.
2. Allow at least **7 days** for community comment.
3. The maintainer(s) make the final call, documented in the issue or PR.

Trivial changes (typos, documentation clarifications, minor bug fixes) can be
merged without the waiting period.

---

## Becoming a Maintainer

There is no formal process yet, but the criteria for nomination are:

- Sustained contributions over at least **3 months** (code, docs, reviews, issue triage).
- Demonstrated understanding of the project's architecture and goals.
- Positive engagement with the community and existing maintainers.

Nomination happens via a public GitHub Issue. Existing maintainers must reach consensus.

## Changing This Document

Proposed changes to this governance document must:

1. Be submitted as a Pull Request with a clear rationale.
2. Remain open for **14 days** for public comment.
3. Receive approval from all current maintainers.
